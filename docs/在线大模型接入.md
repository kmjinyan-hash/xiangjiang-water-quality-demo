# 在线大模型接入

> 当前本机版本（2026-10-22）已改为免登录、用户自带 API。请优先阅读 [自带 API 使用说明](自带API使用说明.md)，在页面顶部“大模型 API”中填写自己的地址、模型和密钥。默认不使用共享环境密钥；下面的环境变量接入内容属于旧服务端配置方式。

负责人要求：**大模型部分先接在线 API**（不接本地 Ollama）。
本文件记录接入方式、边界约定、实测数据与踩过的坑。

## 一、职责边界：模型写"话"，规则定"级"

这是本项目最重要的一条约定。`/api/ai_report` 的处理链是：

```
文本 →〔规则正则抽取〕→〔rules.py 阈值判定〕→〔大模型写结论〕
         ↓抽不到时
       〔大模型兜底解析数值〕→ 仍交给 rules 判定
```

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 指标抽取 | 规则优先，大模型兜底 | 自由文本表述不规则，正则会漏 |
| **等级判定（预警/超标）** | **rules.py** | 必须可复现、可审计；同一组数据不能出现两个结论 |
| 结论叙述 / 处置建议 | 大模型 | 这才是模型的价值 |
| 模型不可用时 | 回落模板摘要 | 外部 API 挂了不能让报告存不下来 |

报告中用 `generated_by` 字段标记来源：

* `llm` —— 结论由大模型生成（前端显示蓝色胶囊「在线大模型 <模型> · <耗时> ms」）
* `rules` —— 结论由规则模板拼接（前端显示灰色「规则引擎生成」）

`rule_summary` 字段始终保留规则摘要，便于对照与追溯。

## 二、配置

密钥**只从环境变量读**，代码与配置文件里没有明文。

```bash
WQ_LLM_API_KEY=sk-xxxx           # 必需；不设则整层禁用，报告回落规则生成
WQ_LLM_BASE_URL=https://api.deepseek.com/v1
WQ_LLM_MODEL=deepseek-flash
WQ_LLM_THINKING=0                # 0=关思考链（默认）
WQ_LLM_TIMEOUT=60
WQ_LLM_MAX_TOKENS=800
WQ_LLM_TEMPERATURE=0.3
```

本地把上面几行写进项目根目录的 `.env`（**已被 `.gitignore` 排除，不会入库**），
`.env.example` 是入库的模板。

容器启动用 `--env-file .env` 注入；compose 用 `${WQ_LLM_API_KEY:-}` 变量替换。
没配密钥时 `/api/llm_status` 返回 `configured: false`，AI 报告仍能正常生成（走规则）。

## 三、实测数据（2026-10-18，DeepSeek）

`deepseek-flash` 可用 model id 只有两个：`deepseek-flash`、`deepseek-v4-pro`。

| 场景 | 延迟 | 说明 |
|---|---|---|
| 默认（含思考链） | 2642 ms | 返回多 `reasoning_content` 853 字 |
| `thinking:{type:"disabled"}` | **1077 ms** | 关闭后快 2.5 倍，输出质量对本场景够用 |
| `deepseek-v4-pro` 关思考 | 2186 ms | 措辞略好，但慢一倍 |

关思考链用请求体参数 `thinking: {"type": "disabled"}`（`reasoning_effort` 也可，
但前者实测更干净）。关闭后响应里不再有 `reasoning_content`。

## 四、踩过的坑（都在 `llm.py` 里修掉了）

### 1. 中文必须按 UTF-8 编码发送

`json.dumps(...).encode('utf-8')` 是必须的。若按本地编码（GBK）发出，
模型会收到乱码，表现为"答非所问"、`prompt_tokens` 异常偏小。
我在 PowerShell 里做的第一次冒烟测试就踩了这个坑，误以为是 API 问题。

### 2. 域名有失效 IP，会导致 21 秒卡顿

`api.deepseek.com` 解析出两个 IP：

```
113.240.66.218    TCP 11 ms     正常
175.12.122.167    TCP 21068 ms  失败(Connection refused)
```

只要先连到坏的那个，就要卡满 ~21 秒等防火墙丢弃 SYN。
表现是"接口偶尔要等 20 多秒"，而模型本身只用了不到 1 秒。

处理方式（`llm.py` 的 `_pinned_host`）：首次请求前用 2.5 秒超时逐个探测，
**只把能连上的地址**交给 `socket.getaddrinfo`，缓存 10 分钟；
请求失败会清缓存重探一次并重试。
TLS 仍按域名做 SNI，证书校验不受影响。

修复后：首次约 3.2 秒（含探测），之后稳定 **354–887 ms**。

### 3. 报告详情读不到 generated_by

`ai_reports` 表原先没有这个字段，写库时被丢弃，导致详情接口读回来永远是空、
前端只能显示「规则引擎生成」。已加 `generated_by` / `llm_meta` 两列，
并在 `_ensure_schema` 里用 `PRAGMA table_info` + `ALTER TABLE` 做**幂等迁移**，
老库重启后自动补列。

## 五、接口

### `GET /api/llm_status`

只报配置，不发请求（毫秒级返回）。密钥打码显示。

```json
{"configured": true, "model": "deepseek-flash", "thinking": false,
 "base_url": "https://api.deepseek.com/v1", "api_key": "YOUR_API_KEY"}
```

带 `?ping=1` 时**真的调一次**模型，用于验收确认网络与密钥可用：
返回延迟、是否开了思考链、token 用量，但**不回显完整回复**。

### `POST /api/ai_report/generate`（SSE 流式）

指定断面，主动让模型生成一份报告，不需要用户粘贴文本。
服务端读取该断面处理后 CSV 的**最后一条记录**，交给 rules 判定等级，
再把「指标 + 判定阈值」交给模型写结论。返回 `text/event-stream`：

```
event: meta   数据 {station, overall, indicators[], date, rule_summary, model, count}
event: delta  数据 {t: "增量文字"}      ← 逐字下发
event: done   数据 {report: {...}}      ← 已入库的完整报告
```

前端用 `fetch` + `ReadableStream` 读取（`EventSource` 不支持 POST），
边收边显示。注意两点：

* **SSE 不能走 gzip**：`_gzip` 里对 `text/event-stream` 直接放行，
  否则整个流会被缓冲成一次性返回，流式效果消失。
* **网络分块不均匀**：一次可能送来整段。前端有显示队列，按约 55 字/秒匀速吐字，
  收到 `done` 后放完剩余字符，再切换成完整报告视图（含逐项判定表）。

## 七、一个必须记住的缓存坑

`_gzip` 原先的缓存键是 `(request.path, ETag or Content-Type)`。
动态 JSON 没有 ETag，键就退化成常量 —— **第一次的响应被永久复用**。
后果不只是"列表不刷新"：

* 报告列表永远停在旧内容；
* 点已删除的报告报 `Report not found`（用户看到的就是"删除时提示取报告失败"）；
* 删除成功了但列表不变，看起来像删除失败。

修复：只缓存**带 ETag** 的响应（即静态文件），动态 JSON 每次现压；
同时给 `/api/*` 的 JSON 响应加 `Cache-Control: no-store`，
防止浏览器启发式缓存再次踩坑。


## 六、迁移到其它厂商

任何 OpenAI 兼容服务（通义千问、智谱、Kimi、OpenAI…）只需改两个环境变量，
代码不用动。注意 `thinking` 参数是本项目为 DeepSeek 加的扩展字段，
不支持的厂商通常会忽略未知字段。
