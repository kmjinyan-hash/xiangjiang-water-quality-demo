# 部署与访问

> 当前本机版（2026-10-22）已取消登录，5000/8443 端口仅绑定 `127.0.0.1`。直接打开 `https://localhost:8443/`，在顶部“大模型 API”填写自己的配置。当前操作请以 [目录与发布说明](目录与发布说明.md) 和 [自带 API 使用说明](自带API使用说明.md) 为准；下文登录、旧管理台与跨机器发布流程保留为历史资料。

## 架构

```
浏览器 ──HTTPS──> Caddy（:8443）
                    ├─ 静态前端：dist/（HTML/CSS/JS）
                    └─ /api/* 反代 ──> Flask（wq:5000，纯 API）
```

**前端与后端彻底分离**：

| | 负责 | 不负责 |
|---|---|---|
| Caddy | 发网页、TLS、gzip、安全响应头 | 业务逻辑 |
| Flask | 只发 JSON；不产出任何 HTML | 静态文件、资源版本号 |

同源部署的好处：不需要 CORS，cookie 可以带 `Secure`，也不会出现"跨域登录后又 401"。

## 启动

```bash
python scripts/build_frontend.py          # 生成 dist/（构建产物，不入库）
docker compose up -d
```

## 访问地址

**必须用主机名，不能用 IP。**

```
https://<主机名>:8443          例如 https://DESKTOP-7D129P8:8443
https://localhost:8443         本机
```

为什么不能用 IP：TLS 的 SNI 规范**禁止 IP 字面量**，浏览器和 curl 对 IP 都不发 SNI，
Caddy 选不出证书就会回 `tls: internal error`。这不是配置错，是协议限制。

`default_sni localhost` 让 IP 访问至少能握上手，但证书名不匹配，浏览器会警告。

## 浏览器证书警告

现在用的是 Caddy 内置 CA 签的自签证书。第一次访问会有"不安全"警告，两种处理：

**① 直接点「继续前往」**（加密仍然有效，只是证书没被系统信任）

**② 信任一次根证书，之后不再警告**（推荐，每台机器做一次）

```powershell
# 导出根证书
docker cp wq_web:/data/caddy/pki/authorities/local/root.crt .\wq-root.crt
```

然后双击 `wq-root.crt` → 安装证书 → 本地计算机 → 受信任的根证书颁发机构 → 完成。
或者用管理员 PowerShell：

```powershell
Import-Certificate -FilePath .\wq-root.crt -CertStoreLocation Cert:\LocalMachine\Root
```

## 登录

首次启动时，如果数据库里没有任何用户，会用 `.env` 里的
`WQ_ADMIN_USER` / `WQ_ADMIN_PASSWORD` 创建管理员。

**没有默认口令**——不配置就不创建，避免 `admin/admin` 这种能被扫到的后门。

管理员登录后可在顶栏「用户管理」里新建/删除用户、重置口令。

## 已知限制

1. **没有域名**：自签证书无法被公共信任，换机器要重新信任一次。要彻底干净需要域名 + 正规证书。
2. **按站点授权未做**：现在 `viewer` 能看全部断面。要"只看指定断面"需再加一层。
3. **用户自助改密未做**：只有管理员能重置口令。

## 前端放到公网（跨源）怎么做

后端已经不含任何前端文件，也不产出 HTML。任何前端（公网的、别人维护的、APK 里的）
只要满足下面两条就能用：

### 1. 允许它的 origin 跨源

```bash
# 同源部署（默认 Caddy 方案）用不到 CORS；
# 前端放到别的域名时，把它的 origin 列进来：
WQ_CORS_ORIGINS=https://app.example.com,https://admin.example.com
```

后端会**回显**请求的 Origin 并加 `Allow-Credentials: true`（带凭证的跨源请求不允许 `*`）。

### 2. 认证改用 Bearer token

**为什么不能用 cookie**：跨站时浏览器不会发送 `SameSite=Lax` 的 cookie，
cookie 模式下公网前端登录后每个请求都会 401。

前端在 `app.config.js` 里设：

```js
authMode: 'bearer'
```

行为变化：
- 登录时自动带 `X-Auth-Mode: bearer` 请求头；
- 后端把 token 放进响应体（`data.token`），不再只依赖 cookie；
- token 存 `localStorage`，之后每个请求带 `Authorization: Bearer <token>`；
- 退出或收到 401 时自动清本地 token。

验证过的调用序列（可直接作为对接文档）：

```http
POST /api/auth/login
Origin: https://app.example.com
X-Auth-Mode: bearer
Content-Type: application/json

{"username":"...","password":"..."}

→ 200 {"ok":true,"data":{"username":"...","role":"admin","token":"...","auth_mode":"bearer"}}
```

```http
GET /api/geo_layers
Origin: https://app.example.com
Authorization: Bearer <token>

→ 200 {"ok":true,"data":[...]}
```

token 是服务端会话，**退出即失效**（库里删一行），不是自包含签名。

### 3. 从哪里知道有哪些接口

`GET /` 返回服务发现（接口分组、认证方式说明），不需要读后端源码：

```json
{"ok":true,"type":"json-api","api_version":"v1","auth":{"cookie":"...","bearer":"..."},"endpoints":{...}}
```

## 已删除的耦合点（本轮）

| 删掉的东西 | 为什么 |
|---|---|
| `Flask(static_folder=...)` | 后端不该当静态服务器 |
| `@app.route('/')` 读 index.html 替换 `%V%` | 构建该由前端自己做 |
| `@app.route('/report')` | 前端路由，后端不该知道 |
| `_asset_version()` / `_ASSET_VER` | 后端遍历前端文件树，纯耦合 |
| `config.FRONTEND_DIR` / `SERVE_FRONTEND` | 后端不该"知道"前端在哪 |
| `Dockerfile` 的 `COPY frontend/` | 后端镜像不含前端 |
| compose 的 `./frontend:/app/frontend` 挂载 | 同上 |

现在 `GET /report`、`/assets/*`、`/index.html` 一律 404，`/` 返回 JSON。

## 前端数据规则（硬约束）

前端是**纯显示器**：只显示后端给的东西，本地不留任何业务数据。

| 类别 | 是否允许 | 说明 |
|---|---|---|
| 图层 / 底图 URL | ✅ | `app.config.js` 里只允许这类 URL |
| 界面偏好（主题） | ✅ | `localStorage: wq.theme`，与数据无关 |
| 断面台账（名称/坐标） | ❌ | 只来自 `GET /api/stations`，前端无副本 |
| 预警阈值 | ❌ | 只来自 `GET /api/ai_warning_rules` |
| 预测/历史/报告 | ❌ | 只来自接口，用完即弃 |
| 用户与权限 | ❌ | 只来自 `GET /api/auth/me`，前端不做任何权限判断 |
| 登录凭证 | ❌ | 只在 HttpOnly cookie 里，JS 读不到也存不了 |
| 地理坐标常量（如流域中心） | ❌ | 地图视图由后端断面范围算出 |

### 已删掉的东西

| 删除项 | 原来是什么 |
|---|---|
| `frontend/assets/js/stations.js` | 14 个断面的名称/坐标/河名/城市（与后端重复） |
| `localStorage: wq_token` | Bearer 模式下的登录凭证（XSS 可读） |
| `app.config.js: initialView` | 硬编码的流域中心坐标 `[27.35, 112.75]` |
| 后端 `X-Auth-Mode: bearer` | 允许把 token 放进响应体交给前端保管 |

### 由此带来的两个行为变化

1. **刷新后主题保留，其余全部重新拉取**（这是期望行为）。
2. **地图初始视图由断面范围决定**，不再固定在某组坐标上；因此新增站点后，
   首屏会自动把新站纳入视野。

### 为什么这么严

前端代码是公开的（按 F12 就能看），任何放在前端的"数据副本"都有三个问题：
会过期（与后端不一致）、会泄露（被看到就是得到）、会被篡改（改本地值绕过显示判断）。
把数据全部收回到后端，前端只剩"请求 + 渲染"，才谈得上"换谁维护都不影响另一边"。
