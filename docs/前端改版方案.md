# 前端改版方案（对照参考系统）

参考：某省空气质量监测与预报可视化平台（Django + 原生 JS + layui + ECharts + OpenLayers）。
本方案把它的 12 个数据展示手法移植到水质场景。**等级分档沿用 `src/water_quality/rules.py` 现有阈值**。

## 一、执行顺序

| 阶段 | 内容 | 为什么排这个位置 |
|---|---|---|
| P0 | ① KPI 卡 ② 等级色块 ③ 趋势参考线 | 视觉骨架，后面所有页面共用 |
| P1 | ④ 断面排行 ⑤ 数据说明页 ⑦ 表格双行值 | 单页即可完成，改动独立 |
| P2 | ⑥ 模型评估页 ⑧ 雷达图 ⑨ 环形图 ⑩ 日历热力图 ⑪ 时间轴播放 ⑫ 导出 | 需要新页面/新图表 |
| 最后 | 前端专属容器（nginx） | 界面稳定后再固化，避免反复重建镜像 |

## 二、数据从哪来（关键，先定死）

前端**只能**从这些接口取数，不得自带任何数据：

| 展示项 | 数据来源 | 字段 |
|---|---|---|
| 断面台账 | `GET /api/stations` | `id,name,role,river,city,lon,lat,code` |
| 各断面最新值 | `GET /api/predict` | `{STID: {DATE, TN, TP, CODMN, NH3N, DO, PH, NTU, TDS, ...}}` |
| 数据新鲜度 | `GET /api/data_status` | `{STID: {latest_date, days_old}}` |
| 阈值与等级 | `GET /api/ai_warning_rules` | 每个指标的 `warning/alarm` 限值 |
| 历史序列 | `GET /api/history/<sid>` | 行数组，含 `DATE` 与各指标 |
| 预测历史 | `GET /api/prediction_history/<sid>` | 同上 |
| 报告 | `GET /api/ai_reports` | 列表（含 `station, overall, generated_by`） |
| AI 短解读 | `POST /api/ai_report/generate`（SSE） | 流式文本 |

**派生指标全部在前端算**（不新增后端接口，保持契约稳定）：
- 超标断面数 = 该断面任一指标超 `alarm` 的计数
- 平均 TN = 各断面 TN 的算术均值（无数据的不计入，并标注 N）
- 最差断面 = 超标指标数最多、其次 TN 最高
- 等级构成 = 按断面最高等级归类计数

> 若以后数据量变大需要后端聚合，再加 `/api/summary`；现在不提前做。

## 三、12 项的具体实现

### ① 顶部 KPI 卡
每页顶部一排 5 张，样式：图标 + 主数字（大字）+ 单位 + 副文本。

大屏/地图页：
1. 断面总数（含"预测断面 5 / 上游输入 9"）
2. 超标断面数（红/绿随值变色）
3. 平均总氮（mg/L，带 N 说明）
4. 最差断面（名称 + TN 值）
5. 数据新鲜度（最新日期 + 距今 N 天，过期变黄）

### ② 等级色块
统一一个 `grade(v, rule)` 函数产出 `{key,label,color}`，全站复用：
- 正常（绿）/ 预警（黄）/ 超标（红）/ 未判（灰）
- 用于：KPI 卡数字、表格等级列、地图圆点、环形图、排行条

### ③ 趋势参考线
ECharts `markLine`：该指标的 `warning`（黄虚线）与 `alarm`（红实线）+ 图例说明。
同时加"近 7 天 / 近 30 天 / 全部"切换（按 `historyLimit` 截取）。

### ④ 断面排行
横向条形图，按 TN 降序（可切换指标），条色 = 等级色，末端标数值。

### ⑤ 数据说明页
新视图「数据说明」，内容：数据来源、各字段含义与单位、更新机制（调度时间）、
评价标准（直接读 `ai_warning_rules` 渲染成表）、已知限制（如模型只预测 TN）。
**规则表必须由接口渲染，不能写死在前端。**

### ⑥ 模型评估页
需要后端补充训练期指标（MAE/R²/基线对比）。**这项目前没有接口** ——
建议先做一个只读的 `GET /api/model_eval`，从模型目录里的元数据文件读，
不现算。等确认元数据结构后再做，避免造数据。

### ⑦ 表格双行值
主行：实测值；次行小字灰：与阈值之比（占标率）。超 `alarm` 标红。

### ⑧ 雷达图
各指标占标率 = 实测 / alarm 限值，7 轴（TN/TP/CODMn/NH3N/DO/NTU/TDS）。
DO 越低越差，需**反向归一**（用 `warning/实测` 或单独处理）。

### ⑨ 环形图
等级构成（正常/预警/超标/未判）与首要超标指标构成。

### ⑩ 日历热力图
按日聚合"超标断面数"，一年一块，颜色深浅表示程度。

### ⑪ 时间轴播放
地图上按 `prediction_history` 的日期逐帧切换圆点颜色，6 秒/帧，可暂停。

### ⑫ 导出
- CSV：`UTF-8 BOM`（Excel 双击不乱码），内容来自当前视图的表格数据
- PNG：地图截图（`leaflet-image` 或 canvas 合成）

## 四、AI 短报告的正确用法（负责人意见）

现状问题：大模型输出**短、不正规**，当"报告"看显得单薄。

改法：**降级为"智能解读"**，嵌在详情页数据旁边：
- 位置：断面详情卡内，「指标卡」下方一小块
- 长度：2–4 句，100 字内
- 内容：只解释"为什么这个断面是这样"，引用具体数值
- 生成：进入详情时按需触发（SSE 流式，像打字），**不落库**
- 正式报告仍走「预警报告」视图，用规则生成 + 模型润色

这样短文本不再是缺陷，而是"旁边有人给你一句话解释"的体验。

> **已实现（2026-10-21）**：`POST /api/ai_report/generate` 新增可选 `style`
> （`report` 默认 / `brief`），brief 用 260 tokens、不写库；前端在断面详情弹窗
> 里加了「AI 一句话解读」块，点按钮才生成（避免每次点断面都产生一次模型费用）。
> 实测输出 ~190 字、2–4 句、引用具体数值，生成后报告列表数量不变。


## 五、两个镜像（上云）

```
wq-backend    Flask，无前端文件，只暴露 5000（内网）
wq-frontend   nginx，发 dist/ 静态，/api/* 反代到 wq-backend，暴露 80/443
```

- 前端容器用 `Dockerfile.frontend` + `nginx.conf`
- 两镜像分别 build、分别 tag，`docker-compose` 同时编排
- 同源部署 → 不再需要 token/CORS 特例，cookie 也可用（但保留 token 兼容打包形态）

## 六、验收

每完成一阶段都跑：
```powershell
python scripts/check_decoupling.py     # 确认没回头耦合
```
并在浏览器里实测（登录 → 断面 → 图表 → 报告），要求 SEVERE 0。
