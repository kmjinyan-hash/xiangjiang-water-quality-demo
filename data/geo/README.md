# data/geo —— 流域矢量边界

把负责人提供的流域边界文件**直接放进这个目录**，系统会自动加载并叠加到地图上。

## 文件名

- 优先读取 `basin.geojson` / `basin.json`
- 没有的话，读取本目录下**最近修改**的 `.geojson` / `.json`
- 所以直接丢一个「湘江流域.geojson」进来也能用，不必改名

## 支持的内容

以下三种都能读：

| 类型 | 说明 |
|---|---|
| `FeatureCollection` | 最常见，可含多个要素 |
| `Feature` | 单个要素 |
| 裸 `Geometry` | `Polygon` / `MultiPolygon` / `LineString` / `MultiLineString` 等 |

## 坐标系（重要）

按 GeoJSON 规范假定为 **WGS-84**，服务端会**自动纠偏为 GCJ-02**（高德底图坐标系）。
不纠偏直接叠加会整体偏移约 600 米 —— 和站点坐标是同一个问题。

- 如果对方给的是 **CGCS2000**：与 WGS-84 在米级精度上一致，按默认处理即可
- 如果对方给的是**已经纠偏过的 GCJ-02 数据**：这里不能再用默认处理，
  否则会二次偏移约 600 米。这种情况需要改成 `already_gcj=True` 调用

## SHP 格式

如果只有 `.shp`，需要 `.shp` / `.shx` / `.dbf` / `.prj` **一整套**：

- 缺 `.prj` 就不知道坐标系，只能靠猜，风险大
- 转成 GeoJSON 后放进来即可（QGIS / ArcGIS / 在线转换都行）

## 目录内容

| 文件 | 说明 |
|---|---|
| `basin.geojson` | 湘江流域边界（面）。WGS-84，后端统一纠偏为 GCJ-02 |
| `landuse.json` | 土地利用的类别表（编码/配色/面积/占比）与名称状态 |
| `tiles/landuse/{z}/{x}/{y}.png` | 土地利用瓦片金字塔，z3–z12，共 1971 张、约 25.6 MB |
| `README.md` | 本文件 |

## 容器里怎么用（重要）

参考数据（边界 + 瓦片）**已烘焙进镜像**，位置是 `/app/geodata`（**不**在挂载点上）。
容器启动时 `docker-entrypoint.sh` 会把它补进 `/app/data/geo`
（`cp -rn`，不覆盖已有文件，所以宿主机改过的文件不会被冲掉）。

这样做的原因：`/app/data` 通常被命名卷挂载，**卷会整体覆盖该目录**，
直接放 `/app/data/geo` 会被遮住 —— 容器就不自包含了，迁移时容易漏东西。

**结论：迁移只需要「镜像 + 命名卷」，不需要额外挂载任何目录。**

```bash
docker run -d --name wq -p 5000:5000 \
  -v wq-data:/app/data -v wq-logs:/app/var/logs \
  smartwaterqualityearlywarningplatform:0.9.1
```

若确实想让宿主机上的改动立即生效（改完刷新页面即可，后端按 mtime 缓存），
再额外绑定挂载覆盖镜像内副本：

```bash
-v "$PWD/data/geo:/app/geodata"
```

## 生效方式

带文件修改时间缓存：**替换文件后刷新页面即可，不需要重启容器**。

## 已验证

在放真实文件之前，用一份覆盖湘江流域的测试矩形验证过整条链路：
API 返回 200、坐标完成纠偏（约 +0.005 / −0.003 度，与站点纠偏量级一致）、
前端渲染为虚线描边的面并压在地图最底层。
